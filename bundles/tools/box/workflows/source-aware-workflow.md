# Source-Aware Workflow

1. Record objective, account or project scope, date, constraints, and authorized owner.
2. Verify current official sources, edition, region, API or feature version, and lifecycle status.
3. Inspect Box API version, enterprise and storage zone, app and OAuth scopes, users and groups, files and folders, ownership, collaborations and shared links, classifications, retention and legal holds, integrations, webhooks, AI settings, events, and audit logs.
4. Separate `Verified`, `Provided`, `Assumed`, and `Needs verification`.
5. Reconcile conflicts among documentation, configuration, permissions, data, integrations, and logs.
6. Draft the Box configuration and use review brief with options, dependencies, privacy and security risks, validation, rollback, and stop conditions.
7. Require explicit confirmation before upload, download, share, move, overwrite or delete content, invite collaborators, change classifications or retention, apply legal holds, use AI, alter users or scopes, or represent governance.
