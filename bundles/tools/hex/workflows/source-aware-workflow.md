# Source-Aware Workflow

1. Record objective, account or project scope, date, constraints, and authorized owner.
2. Verify current official sources, edition, region, API or feature version, and lifecycle status.
3. Inspect workspace and plan, projects and versions, connections and schemas, queries and code, packages and secrets, semantic models and metrics, parameters, schedules and apps, permissions, AI interactions, outputs, logs, lineage, validation, and approvals.
4. Separate `Verified`, `Provided`, `Assumed`, and `Needs verification`.
5. Reconcile conflicts among documentation, configuration, permissions, data, integrations, and logs.
6. Draft the Hex analytical project and deployment review brief with options, dependencies, privacy and security risks, validation, rollback, and stop conditions.
7. Require explicit confirmation before connect or expose data, run code or queries, install packages, use secrets, change metrics, publish apps, schedule jobs, enable AI or MCP, make consequential decisions, or represent analytical results.
