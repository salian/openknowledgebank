# Bitbucket Source-Aware Triage

1. State the decision and direct answer possible now.
2. Record Verified, Provided, Assumed, and Needs verification separately.
3. Inspect the current source version and exact local evidence for Cloud or Data Center product and version, workspace and repository, branches and commits, pull request and reviewers, branch restrictions and merge checks, pipeline YAML, runners, deployment environments, variables, permissions, audit logs, tests, and rollback.
4. Reconcile definitions, identifiers, dates, scope, permissions, processing, and ownership.
5. Record alternatives, stop conditions, and an independent cross-check.
6. Require explicit approval before actions that push or merge code, approve pull requests, run pipelines, deploy releases, change branch restrictions, merge checks, runners, permissions, variables, or secrets.
7. End with a Source Note naming source URLs, user evidence, and missing sources.
