# TeamCity Overview

## Scope

- Projects, build configurations, templates, version-control roots, triggers, build chains and dependencies, agents and pools, parameters, artifacts, tests, investigations, deployments and notifications.
- TeamCity On-Premises and Cloud distinctions, Kotlin DSL, REST API, integrations and plugins, credentials and tokens, roles, clean-up, backup and restore, upgrades, audit evidence, validation, rollback, and controlled CI/CD.

## Evidence Contract

Product documentation can establish documented capabilities. It cannot establish the local edition, configuration, data, access, integration state, execution result, or approval. Inspect current product identity and lifecycle, account or deployment, plan and region, users and roles, configuration, source data, permissions, integrations, logs, controls, validation, rollback, and approval evidence.

## Boundary

Stop before connect repositories, expose credentials, run builds or deployments, change pipelines, agents or permissions, publish artifacts, install plugins, call APIs, upgrade servers, or represent test, build, artifact, deployment, security, or release success without evidenced authority, validation, and explicit confirmation.
