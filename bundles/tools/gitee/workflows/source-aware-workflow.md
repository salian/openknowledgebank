# Source-Aware Workflow

1. Record objective, account or project scope, date, constraints, and authorized owner.
2. Verify current official sources, edition, region, API or feature version, and lifecycle status.
3. Inspect account and edition, repositories and code, branches, organizations, users and permissions, reviews, integrations, workflows, logs, licensing, tests, rollback, and approvals.
4. Separate `Verified`, `Provided`, `Assumed`, and `Needs verification`.
5. Reconcile conflicts among documentation, configuration, permissions, data, integrations, and logs.
6. Draft the Gitee repository and delivery review brief with options, dependencies, privacy and security risks, validation, rollback, and stop conditions.
7. Require explicit confirmation before create or delete repositories, push or merge code, change access, run delivery workflows, publish artifacts, migrate data, or represent review, security, or deployment state.
