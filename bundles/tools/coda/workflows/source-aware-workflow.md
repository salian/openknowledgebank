# Source-Aware Workflow

1. Record objective, account or project scope, date, constraints, and authorized owner.
2. Verify current official sources, edition, region, API or feature version, and lifecycle status.
3. Inspect current product naming and migration status, workspace and plan, documents and ownership, pages and tables, formulas and controls, packs and automations, collaborators and permissions, API or MCP scopes, row and snapshot versions, queued mutation status, integrations, publishing, and audit history.
4. Separate `Verified`, `Provided`, `Assumed`, and `Needs verification`.
5. Reconcile conflicts among documentation, configuration, permissions, data, integrations, and logs.
6. Draft the Superhuman Docs (formerly Coda) configuration and use review brief with options, dependencies, privacy and security risks, validation, rollback, and stop conditions.
7. Require explicit confirmation before create, update, share, publish or delete docs, pages, tables or rows, run automations, install packs, connect API or MCP, expose data, or represent queued writes as complete.
