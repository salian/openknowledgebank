# Source-Aware Workflow

1. Record objective, account or project scope, date, constraints, and authorized owner.
2. Verify current official sources, edition, region, API or feature version, and lifecycle status.
3. Inspect CircleCI version and plan, organization and projects, repositories and revisions, configuration, orbs and dependencies, executors and runners, contexts and secret references, permissions, caches and artifacts, test results, deploy targets, policies, webhooks, insights, audit logs, and rollback state.
4. Separate `Verified`, `Provided`, `Assumed`, and `Needs verification`.
5. Reconcile conflicts among documentation, configuration, permissions, data, integrations, and logs.
6. Draft the CircleCI configuration and use review brief with options, dependencies, privacy and security risks, validation, rollback, and stop conditions.
7. Require explicit confirmation before connect repositories, modify configuration or contexts, expose secrets, approve, rerun or cancel workflows, deploy artifacts, change runners or permissions, or represent build, test, security, or deployment success.
