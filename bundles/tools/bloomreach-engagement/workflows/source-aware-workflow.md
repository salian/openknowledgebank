# Source-Aware Workflow

1. Record objective, account or project scope, date, constraints, and authorized owner.
2. Verify current official sources, edition, region, API or feature version, and lifecycle status.
3. Inspect current Bloomreach Marketing and Engagement naming, account, tenant type and region, projects and environments, customer identifiers, event schemas, consent, tracking, imports, identity merge rules, segments, campaigns, channels, predictions, recommendations, exports, RBAC, and logs.
4. Separate `Verified`, `Provided`, `Assumed`, and `Needs verification`.
5. Reconcile conflicts among documentation, configuration, permissions, data, integrations, and logs.
6. Draft the Bloomreach Engagement configuration and use review brief with options, dependencies, privacy and security risks, validation, rollback, and stop conditions.
7. Require explicit confirmation before collect or import customer data, merge identities, activate segments, send messages, retarget users, change tracking or consent, export profiles, or represent predictions or attribution.
