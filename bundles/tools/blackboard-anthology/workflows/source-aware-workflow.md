# Source-Aware Workflow

1. Record objective, account or project scope, date, constraints, and authorized owner.
2. Verify current official sources, edition, region, API or feature version, and lifecycle status.
3. Inspect current Anthology product and legacy Blackboard naming, deployment and version, institution, courses, users and roles, rosters, content, assessments, grades, accommodations, accessibility, application registration, scopes, integrations, retention, and audit logs.
4. Separate `Verified`, `Provided`, `Assumed`, and `Needs verification`.
5. Reconcile conflicts among documentation, configuration, permissions, data, integrations, and logs.
6. Draft the Anthology Blackboard configuration and use review brief with options, dependencies, privacy and security risks, validation, rollback, and stop conditions.
7. Require explicit confirmation before create or change courses, rosters, content, assessments, grades, accommodations, users, applications, or permissions, expose student data, or represent academic outcomes.
