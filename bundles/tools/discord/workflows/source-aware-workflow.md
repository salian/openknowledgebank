# Source-Aware Workflow

1. Record objective, account or project scope, date, constraints, and authorized owner.
2. Verify current official sources, edition, region, API or feature version, and lifecycle status.
3. Inspect application and API version, server and channel scope, users and roles, OAuth scopes, bot token references, intents and events, commands and interactions, webhooks, message and moderation policy, consent and retention, rate limits, permissions, test environment, and logs.
4. Separate `Verified`, `Provided`, `Assumed`, and `Needs verification`.
5. Reconcile conflicts among documentation, configuration, permissions, data, integrations, and logs.
6. Draft the Discord Developer Platform configuration and use review brief with options, dependencies, privacy and security risks, validation, rollback, and stop conditions.
7. Require explicit confirmation before create or install applications or bots, issue tokens, read or send messages, change roles or moderation, access member data, invoke webhooks, or represent delivery or authorization.
