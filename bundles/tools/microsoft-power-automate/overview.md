# Microsoft Power Automate Overview

Source-aware guidance for flow design, connectors, credentials, data handling, error controls, testing, and governed activation.

## Evidence Contract

Relevant evidence includes tenant, environment, licenses, flow type, triggers, actions, connectors, connection references, credential scopes, schemas, DLP policies, error handling, run history, tests, owners, and approvals. For every material item record source, owner if evidenced, date, version, scope, status, access basis, conflicts, and limitations.

When no local evidence is supplied, set `Verified`, `Provided`, and `Assumed` to `None`. Put exact missing artifacts under `Needs verification`. A general disclaimer is not a substitute for requesting evidence.

## Boundary

Analysis and drafting do not establish Flow configuration, connector capability, credential scope, data values, DLP state, run outcome, downstream effects, and cost. Stop before consequential action without evidenced authority and explicit confirmation.
