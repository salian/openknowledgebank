# Source-Aware Workflow

1. Record objective, account or project scope, date, constraints, and authorized owner.
2. Verify current official sources, edition, region, API or feature version, and lifecycle status.
3. Inspect organization and plan, API version, repositories and revisions, pipelines and steps, agents and clusters, queues, secrets references, tokens and scopes, teams and permissions, artifacts, test results, schedules, integrations, audit events, and rollback state.
4. Separate `Verified`, `Provided`, `Assumed`, and `Needs verification`.
5. Reconcile conflicts among documentation, configuration, permissions, data, integrations, and logs.
6. Draft the Buildkite configuration and use review brief with options, dependencies, privacy and security risks, validation, rollback, and stop conditions.
7. Require explicit confirmation before connect repositories, create or change pipelines, issue or revoke tokens, run, retry or cancel builds, change agents, queues, teams or secrets, publish packages, or deploy artifacts.
