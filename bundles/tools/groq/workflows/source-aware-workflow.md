# Source-Aware Workflow

1. Record objective, account or project scope, date, constraints, and authorized owner.
2. Verify current official sources, edition, region, API or feature version, and lifecycle status.
3. Inspect organization and project, model and endpoint, keys and scopes, prompts and parameters, files, audio, tools and functions, outputs and citations, usage and limits, retention controls, logs, evaluations, fallbacks, rollback, and approvals.
4. Separate `Verified`, `Provided`, `Assumed`, and `Needs verification`.
5. Reconcile conflicts among documentation, configuration, permissions, data, integrations, and logs.
6. Draft the GroqCloud inference implementation and risk review brief with options, dependencies, privacy and security risks, validation, rollback, and stop conditions.
7. Require explicit confirmation before upload sensitive data, enable tools, call functions, fine-tune, publish generated output, deploy inference, incur spend, or represent factuality, safety, latency, or completion.
