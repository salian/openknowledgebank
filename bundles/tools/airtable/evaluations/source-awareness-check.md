# Airtable Source-Awareness Check

Check that responses answer directly, preserve prompt facts, name applicable authoritative URLs, separate evidence states, avoid inventing schema, record count, formula result, permission, automation state, synchronization, API completeness, or source-of-record status, leave unevidenced reviewers and provenance as `Needs verification`, define conflict checks, and require confirmation before actions that create or modify records or schema, share a base, invite users, enable automations, create webhooks, expose tokens, or overwrite synchronized data.
