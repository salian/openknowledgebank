# Source-Aware Workflow

1. Record objective, account or project scope, date, constraints, and authorized owner.
2. Verify current official sources, edition, region, API or feature version, and lifecycle status.
3. Inspect account and plan, site ownership, tracking code and scope, consent and privacy requirements, masking, snapshots and recordings, traffic sources, goals, segments, survey responses, experiment design and allocation, metrics, sample size, exclusions, integrations, and reports.
4. Separate `Verified`, `Provided`, `Assumed`, and `Needs verification`.
5. Reconcile conflicts among documentation, configuration, permissions, data, integrations, and logs.
6. Draft the Crazy Egg configuration and use review brief with options, dependencies, privacy and security risks, validation, rollback, and stop conditions.
7. Require explicit confirmation before install or change tracking, enable recordings, alter masking, launch or stop tests, collect surveys, change site variants, export visitor data, or represent causality or conversion lift.
