# Source-Aware Workflow

1. Record objective, account or project scope, date, constraints, and authorized owner.
2. Verify current official sources, edition, region, API or feature version, and lifecycle status.
3. Inspect account and modules, organizations and projects, connectors and secrets, services and environments, infrastructure, pipelines and artifacts, feature flags, policies and approvals, costs, findings, incidents, logs, tests, rollback, and approvals.
4. Separate `Verified`, `Provided`, `Assumed`, and `Needs verification`.
5. Reconcile conflicts among documentation, configuration, permissions, data, integrations, and logs.
6. Draft the Harness software delivery and governance review brief with options, dependencies, privacy and security risks, validation, rollback, and stop conditions.
7. Require explicit confirmation before run pipelines, deploy code, change infrastructure or feature flags, expose secrets, approve policies, remediate findings, alter budgets, manage incidents, or represent delivery or security state.
