# Source-Aware Workflow

1. Record objective, account or project scope, date, constraints, and authorized owner.
2. Verify current official sources, edition, region, API or feature version, and lifecycle status.
3. Inspect Camtasia version license and operating environment, approved brief and audience, source captures media scripts brand assets fonts and rights, recording consent and personal-data boundaries, project timeline tracks effects captions audio descriptions quizzes and SCORM settings, accessibility review, export codec resolution platform and LMS requirements, learner-data handling, playback tests source package approvals and handoff authority.
4. Separate `Verified`, `Provided`, `Assumed`, and `Needs verification`.
5. Reconcile conflicts among documentation, configuration, permissions, data, integrations, and logs.
6. Draft the Camtasia recording, edit, accessibility, export-validation, and handoff package with options, dependencies, privacy and security risks, validation, rollback, and stop conditions.
7. Require explicit confirmation before record a person screen system or confidential data, import or publish protected media, alter source projects, create quizzes or SCORM packages, upload to an LMS or platform, collect learner data, or represent accessibility rights clearance learning results or approval.
