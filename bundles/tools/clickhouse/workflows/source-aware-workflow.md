# Source-Aware Workflow

1. Record objective, account or project scope, date, constraints, and authorized owner.
2. Verify current official sources, edition, region, API or feature version, and lifecycle status.
3. Inspect edition and version, cloud or self-managed topology, databases and schemas, table engines and partitions, data classifications, ingestion pipelines, queries and workloads, users and grants, network and encryption settings, replication, quotas, storage and cost, backups and restores, monitoring, and logs.
4. Separate `Verified`, `Provided`, `Assumed`, and `Needs verification`.
5. Reconcile conflicts among documentation, configuration, permissions, data, integrations, and logs.
6. Draft the ClickHouse configuration and use review brief with options, dependencies, privacy and security risks, validation, rollback, and stop conditions.
7. Require explicit confirmation before provision or resize resources, create or alter schemas, ingest, query, export or delete data, change grants or networking, run migrations, restore backups, or represent performance or recovery.
