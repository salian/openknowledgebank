# Source-Aware Workflow

1. Record objective, account or project scope, date, constraints, and authorized owner.
2. Verify current official sources, edition, region, API or feature version, and lifecycle status.
3. Inspect subscription, region, jobs, candidates, applications, sources, consent and retention, interview plans, scorecards, calendars, offers, permissions, integrations, automations, and audit logs.
4. Separate `Verified`, `Provided`, `Assumed`, and `Needs verification`.
5. Reconcile conflicts among documentation, configuration, permissions, data, integrations, and logs.
6. Draft the Ashby configuration and use review brief with options, dependencies, privacy and security risks, validation, rollback, and stop conditions.
7. Require explicit confirmation before create or publish jobs, contact or move candidates, schedule interviews, submit evaluations, issue offers, change retention, export personal data, or represent a hiring decision.
