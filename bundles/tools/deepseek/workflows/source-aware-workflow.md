# Source-Aware Workflow

1. Record objective, account or project scope, date, constraints, and authorized owner.
2. Verify current official sources, edition, region, API or feature version, and lifecycle status.
3. Inspect current model and dated revision, API format and endpoint, account and region, data handling, credentials, prompts and system instructions, tool definitions and permissions, inputs and classifications, parameters, outputs, usage and cost, safety tests, evaluations, monitoring, and approvals.
4. Separate `Verified`, `Provided`, `Assumed`, and `Needs verification`.
5. Reconcile conflicts among documentation, configuration, permissions, data, integrations, and logs.
6. Draft the DeepSeek API configuration and use review brief with options, dependencies, privacy and security risks, validation, rollback, and stop conditions.
7. Require explicit confirmation before send sensitive data, call production models or tools, expose credentials, automate decisions, publish generated content, change systems, or represent model output as factual or approved.
