# Source-Aware Workflow

1. Record objective, account or project scope, date, constraints, and authorized owner.
2. Verify current official sources, edition, region, API or feature version, and lifecycle status.
3. Inspect plan and API version, application and credentials, document version and ownership, signer identities and authority, recipient roles and order, consent and disclosure, fields and templates, authentication, jurisdiction and transaction type, callbacks, retention, request events, and executed record.
4. Separate `Verified`, `Provided`, `Assumed`, and `Needs verification`.
5. Reconcile conflicts among documentation, configuration, permissions, data, integrations, and logs.
6. Draft the Dropbox Sign configuration and use review brief with options, dependencies, privacy and security risks, validation, rollback, and stop conditions.
7. Require explicit confirmation before send or cancel signature requests, create embedded or public signing flows, change documents or recipients, authenticate signers, countersign, expose API credentials, retain or delete records, or represent enforceability.
