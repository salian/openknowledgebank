# Source-Aware Workflow

1. Record objective, account or project scope, date, constraints, and authorized owner.
2. Verify current official sources, edition, region, API or feature version, and lifecycle status.
3. Inspect workspace and region, SDK and API versions, user identifiers, events and attributes, consent and subscriptions, identity rules, segments, campaigns and Canvases, templates, channels, frequency and quiet-time settings, experiments, integrations, reports, and logs.
4. Separate `Verified`, `Provided`, `Assumed`, and `Needs verification`.
5. Reconcile conflicts among documentation, configuration, permissions, data, integrations, and logs.
6. Draft the Braze configuration and use review brief with options, dependencies, privacy and security risks, validation, rollback, and stop conditions.
7. Require explicit confirmation before collect or export user data, merge identities, change subscriptions, activate segments or journeys, send messages, run experiments, use credentials, or represent engagement results.
