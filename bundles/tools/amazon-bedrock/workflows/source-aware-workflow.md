# Source-Aware Workflow

1. Record objective, account or project scope, date, constraints, and authorized owner.
2. Verify current official sources, edition, region, API or feature version, and lifecycle status.
3. Inspect AWS account and region, service and model availability, model version, data classification, IAM, encryption, network controls, prompts, knowledge sources, guardrails, evaluations, quotas, costs, and logs.
4. Separate `Verified`, `Provided`, `Assumed`, and `Needs verification`.
5. Reconcile conflicts among documentation, configuration, permissions, data, integrations, and logs.
6. Draft the Amazon Bedrock configuration and use review brief with options, dependencies, privacy and security risks, validation, rollback, and stop conditions.
7. Require explicit confirmation before enable models, transmit data, create agents or knowledge bases, change IAM or guardrails, deploy inference, incur spend, or represent safety or quality approval.
