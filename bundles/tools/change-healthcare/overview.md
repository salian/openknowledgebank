# Optum APIs (formerly Change Healthcare) Overview

## Scope

- Current Optum developer APIs and healthcare administrative, clinical, payment, eligibility, claims, and interoperability workflows formerly associated with Change Healthcare.
- Applications, credentials, endpoints, environments, healthcare transactions, integrations, monitoring, and operational controls.

## Evidence Contract

Product documentation can establish documented capabilities. It cannot establish the local edition, configuration, data, access, integration state, execution result, or approval. Inspect current product ownership and migration status, API product and version, environment, organization and trading partners, credentials and scopes, patient and member identity, consent and authorization, transaction formats, claims and eligibility data, payer rules, mappings, acknowledgments, errors, integrations, security controls, and audit logs.

## Boundary

Stop before access or transmit protected health information, query eligibility, submit or alter claims or payments, change trading-partner configuration, issue credentials, call production APIs, or represent clinical, coverage, payment, or compliance outcomes without evidenced authority, validation, and explicit confirmation.
