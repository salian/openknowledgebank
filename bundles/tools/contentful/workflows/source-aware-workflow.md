# Source-Aware Workflow

1. Record objective, account or project scope, date, constraints, and authorized owner.
2. Verify current official sources, edition, region, API or feature version, and lifecycle status.
3. Inspect plan and API version, organization and spaces, environments and aliases, content types and validations, entries and assets, locales, references, workflows and releases, users and roles, tokens and scopes, apps and webhooks, caches and delivery settings, migrations, version conflicts, and audit logs.
4. Separate `Verified`, `Provided`, `Assumed`, and `Needs verification`.
5. Reconcile conflicts among documentation, configuration, permissions, data, integrations, and logs.
6. Draft the Contentful configuration and use review brief with options, dependencies, privacy and security risks, validation, rollback, and stop conditions.
7. Require explicit confirmation before create or alter content models, entries, assets or environments, issue tokens, install apps, run migrations, publish, unpublish or delete content, change roles, or represent delivery.
