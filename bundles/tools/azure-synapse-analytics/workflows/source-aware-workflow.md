# Source-Aware Workflow

1. Record objective, account or project scope, date, constraints, and authorized owner.
2. Verify current official sources, edition, region, API or feature version, and lifecycle status.
3. Inspect Azure subscription, tenant and region, workspace, network boundaries, identities and RBAC, linked services, credentials references, data classifications, SQL and Spark pools, pipelines, notebooks, costs, policies, logs, and recovery state.
4. Separate `Verified`, `Provided`, `Assumed`, and `Needs verification`.
5. Reconcile conflicts among documentation, configuration, permissions, data, integrations, and logs.
6. Draft the Azure Synapse Analytics configuration and use review brief with options, dependencies, privacy and security risks, validation, rollback, and stop conditions.
7. Require explicit confirmation before provision or resize resources, connect data sources, execute queries or pipelines, change networking or access, expose secrets or data, delete resources, or represent analytics as validated.
