# Source-Aware Workflow

1. Record objective, account or project scope, date, constraints, and authorized owner.
2. Verify current official sources, edition, region, API or feature version, and lifecycle status.
3. Inspect Drupal core version, hosting and PHP stack, site and environment, modules and themes with versions and provenance, content types and workflows, users and permissions, media rights, configuration, custom code, integrations, caching, backups, security advisories, tests, and rollback state.
4. Separate `Verified`, `Provided`, `Assumed`, and `Needs verification`.
5. Reconcile conflicts among documentation, configuration, permissions, data, integrations, and logs.
6. Draft the Drupal configuration and use review brief with options, dependencies, privacy and security risks, validation, rollback, and stop conditions.
7. Require explicit confirmation before install or update code, modules or themes, change schemas, content, workflows or permissions, run database updates, publish or delete content, deploy configuration, or represent security or compatibility.
