# Source-Aware Workflow

1. Record objective, account or project scope, date, constraints, and authorized owner.
2. Verify current official sources, edition, region, API or feature version, and lifecycle status.
3. Inspect organization facility tenant version lifecycle and enabled modules, licensed care settings and approved workflows, patient provider encounter and master-data identity controls, users roles authentication and permissions, clinical documentation order medication decision-support scheduling and revenue-cycle configurations, interface FHIR vocabulary device and downstream mappings, test environment scripts clinical-safety and usability review, privacy security audit retention downtime business-continuity migration reconciliation rollback approvals and release authority.
4. Separate `Verified`, `Provided`, `Assumed`, and `Needs verification`.
5. Reconcile conflicts among documentation, configuration, permissions, data, integrations, and logs.
6. Draft the MEDITECH Expanse clinical workflow, interoperability, migration, validation, downtime, and release brief with options, dependencies, privacy and security risks, validation, rollback, and stop conditions.
7. Require explicit confirmation before access an environment or patient record, create alter migrate reconcile or disclose clinical or billing data, configure workflows orders medications alerts identities roles interfaces or FHIR access, release to production, or represent clinical correctness safety interoperability reimbursement compliance or approval.
