# Source-Aware Workflow

1. Record objective, account or project scope, date, constraints, and authorized owner.
2. Verify current official sources, edition, region, API or feature version, and lifecycle status.
3. Inspect deployment and version, repositories, branches, organizations, users and permissions, authentication, secrets, runners, workflows, packages, webhooks, logs, backups, tests, rollback, and approvals.
4. Separate `Verified`, `Provided`, `Assumed`, and `Needs verification`.
5. Reconcile conflicts among documentation, configuration, permissions, data, integrations, and logs.
6. Draft the Gitea deployment and repository operations review brief with options, dependencies, privacy and security risks, validation, rollback, and stop conditions.
7. Require explicit confirmation before create or delete repositories, merge code, change access, run workflows, expose secrets, publish packages, upgrade or migrate a server, restore backups, or represent security or deployment state.
