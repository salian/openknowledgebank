# SonarQube Overview

## Scope

- Static analysis across supported languages, bugs, vulnerabilities, code smells and security hotspots, rules and quality profiles, quality gates, branches and pull requests, measures, dashboards, reports and IDE or CI integration.
- Server and Cloud edition and release distinctions, project onboarding, tokens, webhooks and APIs, portfolios and governance features where licensed, permissions, exclusions, baseline or new-code settings, validation, and controlled enforcement.

## Evidence Contract

Product documentation can establish documented capabilities. It cannot establish the local edition, configuration, data, access, integration state, execution result, or approval. Inspect current product identity and lifecycle, account or deployment, plan and region, users and roles, configuration, source data, permissions, integrations, logs, controls, validation, rollback, and approval evidence.

## Boundary

Stop before scan proprietary code, change rules or quality gates, suppress or resolve findings, expose tokens, block merges, connect repositories, or represent issue validity, vulnerability, risk, coverage, quality, compliance, or release readiness without evidenced authority, validation, and explicit confirmation.
