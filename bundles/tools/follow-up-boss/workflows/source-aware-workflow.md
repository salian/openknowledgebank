# Source-Aware Workflow

1. Record objective, account or project scope, date, constraints, and authorized owner.
2. Verify current official sources, edition, region, API or feature version, and lifecycle status.
3. Inspect account edition and lifecycle, business and team structure, lead sources and ownership rules, consent opt-out and do-not-call evidence, users roles and permissions, routing stages action plans and communication settings, integrations API fields and mappings, duplicate merge migration and attribution rules, privacy retention audit tests rollback approvals and release authority.
4. Separate `Verified`, `Provided`, `Assumed`, and `Needs verification`.
5. Reconcile conflicts among documentation, configuration, permissions, data, integrations, and logs.
6. Draft the Follow Up Boss configuration, migration, communications-control, validation, and release brief with options, dependencies, privacy and security risks, validation, rollback, and stop conditions.
7. Require explicit confirmation before access an account, create alter route merge import export or delete lead records, call text or email people, change roles workflows or integrations, attribute revenue, or represent consent lead status conversion compliance or approval.
