# Source-Aware Workflow

1. Record objective, account or project scope, date, constraints, and authorized owner.
2. Verify current official sources, edition, region, API or feature version, and lifecycle status.
3. Inspect account, region and edition, API version and credentials, customer identifiers, event and catalog schemas, consent and suppression, identity rules, audiences, journeys, campaigns, templates, channels, recommendations, integrations, attribution, and logs.
4. Separate `Verified`, `Provided`, `Assumed`, and `Needs verification`.
5. Reconcile conflicts among documentation, configuration, permissions, data, integrations, and logs.
6. Draft the Blueshift configuration and use review brief with options, dependencies, privacy and security risks, validation, rollback, and stop conditions.
7. Require explicit confirmation before ingest or export customer data, merge identities, create or activate audiences or journeys, send messages, change consent or suppression, use credentials, or represent campaign outcomes.
