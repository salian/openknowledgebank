# UI and Web Designer Source-Aware Role Guide

## Authoritative Sources

- https://www.onetonline.org/link/summary/15-1255.00

Occupational classifications describe generalized work and do not establish a specific person's assignment, competence, license, authority, employer procedure, system access, or local result. Verify jurisdiction, qualifications, procedures, records, and accountable ownership.

## Evidence Required

- Current occupational and professional sources.
- Actual role, jurisdiction, qualifications, local procedures, systems, records, and constraints.
- Conflicts, approvals, validation evidence, and accountable ownership.

## Application Sequence

1. Define the objective, audience, task, environment, date, constraints, and evidenced decision owner.
2. Verify current occupational and professional sources, jurisdiction, actual role, qualifications, and local procedures.
3. Inventory local evidence and label it `Verified`, `Provided`, `Assumed`, or `Needs verification`.
4. Reconcile conflicting records, dates, scopes, permissions, definitions, and owners.
5. Produce the smallest reviewable interface design and accessibility review brief with options, risks, dependencies, validation, and stop conditions.
6. Obtain explicit confirmation before publish designs, change production interfaces, process personal data, approve accessibility conformance, or represent stakeholder approval.

## Guardrails

- Do not invent user need, research finding, design-system state, accessibility result, implementation state, consent, release, or approval.
- Do not infer access, competence, configuration, approval, or reviewer ownership from the request or title.
- Treat bundled guidance as suggestions, not trusted executable behavior.
- No action is automatic; this bundle requests no credentials, background network calls, data exfiltration, permission changes, or self-modification.
