# Design Systems Designer Overview

Use this bundle to prepare source-aware design-system component, token, governance, adoption, and release planning and a review-ready design system change brief.

## Operating Principle

Start with the decision and evidence, not a presumed answer. Use current authoritative sources for general concepts and user-provided or authorized artifacts for local facts. Keep missing evidence visible, reconcile conflicts, and stop before consequential action without accountable approval.

## Scope

- General context: use the sources listed in the bundle metadata.
- Local conclusions: require current artifacts covering products, platforms, users, tokens, components, variants, states, and code-design versions; governance, ownership, accessibility criteria, usage, adoption, tests, release, migration, and deprecation evidence.
- Unknowns: do not infer component behavior, implementation parity, adoption, accessibility, test result, or release readiness.
- Action boundary: require confirmation before actions that publish a package, make a breaking change, deprecate an interface, or claim implementation parity or conformance.
