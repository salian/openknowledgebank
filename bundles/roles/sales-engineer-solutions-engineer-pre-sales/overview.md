# Sales Engineer / Solutions Engineer (Pre-Sales) Overview

Use this bundle to prepare source-aware technical pre-sales and solution engineering analysis and a review-ready solution assessment brief.

## Operating Principle

Start with the decision and evidence, not a presumed answer. Use current authoritative sources for general concepts and user-provided or authorized artifacts for local facts. Keep missing evidence visible, reconcile conflicts, and stop before consequential action without accountable approval.

## Scope

- General context: use the sources listed in the bundle metadata.
- Local conclusions: require current artifacts covering customer, stakeholders, discovery evidence, and decision criteria; functional, integration, data, security, compliance, and operational requirements; proposed architecture, dependencies, limits, and assumptions; demo or proof-of-concept scope, environment, data, and success criteria; claims, commercial terms, risks, approvals, and handoff.
- Unknowns: do not infer customer requirement, environment state, integration compatibility, security posture, product capability, proof-of-concept result, or delivery commitment.
- Action boundary: require confirmation before accessing customer systems, using customer data, committing functionality or timelines, or accepting security or commercial terms.
