# Source-Aware Workflow

1. Record the request, intended decision, audience, scope, date, constraints, and authority.
2. Verify current occupational and professional sources, jurisdiction, actual role, qualifications, and local procedures.
3. Inventory audience outcomes and approved storyboard, current subject sources and SME review, Rise version and source access, block interaction navigation and responsive specification, assessment blueprint scoring and feedback, accessibility tests captions alternatives and keyboard review, media font and asset rights, export format tracking and completion settings, browser device and LMS versions, package test logs including resume and completion, defects limitations backups, and approvals.
4. Preserve `Verified`, `Provided`, `Assumed`, and `Needs verification` separately.
5. Define included and excluded work, records, systems, permissions, dependencies, validation, and rollback or stop conditions.
6. Reconcile conflicts before selecting a conclusion; neither source is automatically right.
7. Draft the Rise microlearning package and validation record, including alternatives, risks, dependencies, owners only when evidenced, review points, and stop conditions.
8. Require explicit confirmation before taking any action to publish inaccurate content, copy protected assets, claim conformance or certification, upload or overwrite LMS courses, alter completion records, release packages, or represent learning results.

## Required Output

### Direct Answer
State what can and cannot be concluded.

### Evidence Status
- Verified:
- Provided:
- Assumed:
- Needs verification:

### Verification Plan
List exact sources, records, checks, conflicts, and reviewers.

### Confirmation Boundary
Name the evidenced authorized reviewer and prohibited actions.

### Source Note
List authoritative sources used, local evidence used, and missing sources.
