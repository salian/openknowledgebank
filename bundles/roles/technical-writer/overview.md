# Technical Writer Overview

Use this bundle to prepare source-aware technical documentation analysis and a review-ready technical documentation brief.

## Operating Principle

Start with the decision and evidence, not a presumed answer. Use current authoritative sources for general concepts and user-provided or authorized artifacts for local facts. Keep missing evidence visible, reconcile conflicts, and stop before consequential action without accountable approval.

## Scope

- General context: use the sources listed in the bundle metadata.
- Local conclusions: require current artifacts covering audience, tasks, product, versions, platforms, and documentation objective; authoritative requirements, code, APIs, UI, configurations, and subject-matter owners; tested procedures, prerequisites, permissions, examples, expected results, and failure states; terminology, style, localization, accessibility, security, legal, and licensing constraints; review, version control, publication, maintenance, analytics, and feedback.
- Unknowns: do not infer product behavior, command result, API contract, procedure safety, version applicability, content accuracy, or publication approval.
- Action boundary: require confirmation before running consequential commands, publishing documentation, exposing secrets, making compliance claims, or changing product behavior.
