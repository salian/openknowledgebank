# Application Integration / API Engineer Overview

Use this bundle to prepare source-aware application integration and API engineering analysis and a review-ready integration delivery brief.

## Operating Principle

Start with the decision and evidence, not a presumed answer. Use current authoritative sources for general concepts and user-provided or authorized artifacts for local facts. Keep missing evidence visible, reconcile conflicts, and stop before consequential action without accountable approval.

## Scope

- General context: use the sources listed in the bundle metadata.
- Local conclusions: require current artifacts covering integration objective, systems, owners, and environments; API specifications, schemas, versions, and compatibility; authentication, authorization, secrets, and network boundaries; data mappings, transformations, validation, and error handling; dependencies, rate limits, retries, idempotency, observability, tests, deployment, and rollback.
- Unknowns: do not infer API behavior, field meaning, compatibility, authorization, delivery semantics, test result, or production state.
- Action boundary: require confirmation before accessing systems, changing API contracts, deploying integrations, modifying credentials or access, or moving production data.
