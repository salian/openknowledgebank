# Source-Aware Workflow

1. Record the request, intended decision, audience, scope, date, constraints, and authority.
2. Verify current occupational and professional sources, jurisdiction, actual role, qualifications, and local procedures.
3. Inventory domain property and environment authority, platform and template versions, crawl and server logs, Search Console exports, robots and sitemap versions, URL inventory and faceting rules, rendering tests, canonical and redirect evidence, catalog product variant price and availability sources, structured-data outputs and validation, analytics and conversion definitions, migration dependencies, accessibility and privacy review, release and rollback plan, and approvals.
4. Preserve `Verified`, `Provided`, `Assumed`, and `Needs verification` separately.
5. Define included and excluded work, records, systems, permissions, dependencies, validation, and rollback or stop conditions.
6. Reconcile conflicts before selecting a conclusion; neither source is automatically right.
7. Draft the enterprise ecommerce technical SEO audit and release plan, including alternatives, risks, dependencies, owners only when evidenced, review points, and stop conditions.
8. Require explicit confirmation before taking any action to access systems without authority, change robots canonicals redirects templates or schema, expose logs or user data, deploy migrations, request indexing, or represent ranking, traffic, conversion, or revenue.

### Source Note
List authoritative sources used, local evidence used, and missing sources.
