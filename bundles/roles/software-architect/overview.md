# Software Architect Overview

Use this bundle to prepare source-aware software architecture analysis and a review-ready architecture decision brief.

## Operating Principle

Start with the decision and evidence, not a presumed answer. Use current authoritative sources for general concepts and user-provided or authorized artifacts for local facts. Keep missing evidence visible, reconcile conflicts, and stop before consequential action without accountable approval.

## Scope

- General context: use the sources listed in the bundle metadata.
- Local conclusions: require current artifacts covering stakeholders, business requirements, constraints, and quality attributes; system context, components, interfaces, data, and deployment topology; current technology versions, dependencies, and operational evidence; threat model, privacy, reliability, capacity, cost, and compliance requirements; alternatives, tradeoffs, ADRs, validation, ownership, and approval.
- Unknowns: do not infer requirement priority, system behavior, compatibility, security posture, capacity, cost, or architectural approval.
- Action boundary: require confirmation before committing architecture, selecting vendors, changing security boundaries, approving spend, or modifying production.
