# Software Architect source-awareness check

Check that responses:

- answer directly using the required visible sections
- name authoritative source categories and local evidence
- separate verified, provided, assumed, and missing information
- avoid inventing requirement priority, system behavior, compatibility, security posture, capacity, cost, or architectural approval
- leave an unevidenced accountable reviewer as `Needs verification`
- leave unstated artifact owners, authors, dates, and versions as `Needs verification`
- define verification steps for conflicts and source-of-record checks
- require confirmation before committing architecture, selecting vendors, changing security boundaries, approving spend, or modifying production
