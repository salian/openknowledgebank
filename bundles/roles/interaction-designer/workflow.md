# Interaction Design Review Workflow

1. Record the request, intended audience, decision, user and task scope, product or service context, platform, evidence supplied, and evidence date.
2. Inventory approved research, requirements, business rules, service and content context, current flows, design-system patterns, implementation evidence, accessibility target, and approval paths without accessing unprovided systems.
3. Map interaction, visual design, research, service design, content, engineering, product, accessibility, and governance responsibilities; mark unsupported ownership `Needs verification`.
4. Define actors, goals, entry and exit conditions, happy and alternate paths, states, transitions, input modes, feedback, errors, interruptions, cancellation, undo, retry, and recovery.
5. Trace every behavior to provided evidence, an explicit hypothesis, a standard requirement, or an unresolved question.
6. Review applicable accessibility and inclusive-design needs, preserving the distinction between normative requirements, informative patterns, design evidence, implementation evidence, and conformance claims.
7. Define a prototype or test only around a named question; state simulation limits, research governance, participant needs, evidence collection, and decision criteria.
8. Draft the interaction model, state specification, accessible-flow review, or handoff with source note, evidence states, assumptions, unresolved rules, test needs, and accountable review needs.
9. Apply the quality check for missing states, invented evidence, role overreach, implementation assumptions, and unsupported conformance.
10. Stop before participant contact, private-data or repository access, design-system or production changes, publication, release, procurement, or certification.

Use the [role guide](role.md) for controls and the [quality check](evaluations/quality-check.md) before relying on the output.
