# Site Reliability Engineer (SRE) Overview

Use this bundle to prepare source-aware site reliability engineering analysis and a review-ready service reliability brief.

## Operating Principle

Start with the decision and evidence, not a presumed answer. Use current authoritative sources for general concepts and user-provided or authorized artifacts for local facts. Keep missing evidence visible, reconcile conflicts, and stop before consequential action without accountable approval.

## Scope

- General context: use the sources listed in the bundle metadata.
- Local conclusions: require current artifacts covering service, users, critical journeys, owners, and production scope; SLI definitions, data sources, SLO windows, targets, and error-budget policy; architecture, dependencies, failure modes, and change history; monitoring, alerts, incidents, runbooks, postmortems, capacity, access, deployment, and rollback evidence.
- Unknowns: do not infer service health, SLI validity, SLO attainment, error-budget consumption, incident cause, capacity, or production state.
- Action boundary: require confirmation before changing production, deploying releases, modifying alerts or access, using credentials, or issuing incident communications.
