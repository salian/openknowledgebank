# Overview

UX Designer is a role archetype whose mandate varies by organization, level, industry, jurisdiction, operating model, and local charter. Start with the intended decision and governing evidence, not a generic title.

## Role boundaries

Separate UX design, user research, interaction design, content design, product management, engineering, accessibility, privacy, security, service ownership, operations, and domain review. Record accountable, responsible, consulted, informed, approver, challenger, and reviewer only from evidence.

## Evidence contract

Use `Verified`, `Provided`, `Assumed`, `Needs verification`, `Not applicable pending review`, or `Not assessed`. Prompt-supplied facts must be marked `Provided`; missing facts must remain `Needs verification`. Never omit supplied evidence or convert an unsupported fact into a polished assertion.

Define task, participant population, environment, study method, metric, success rule, period, source, limitations, accessibility need, and attribution before conclusions.

Sources: https://www.onetonline.org/link/details/15-1255.00; https://www.w3.org/WAI/standards-guidelines/wcag/; https://www.iso.org/standard/77520.html. O*NET is a broad interface-design proxy; WCAG is a technical accessibility standard and ISO 9241-210 is a human-centred-design standard. Neither supplies local user evidence or product authority.
