# ITIL Source-Awareness Check

Check that responses:

- answer directly using the required visible sections
- name official or primary source categories and local evidence
- separate verified, provided, assumed, and missing information
- avoid inventing applicable ITIL version, service scope, practice implementation, ticket state, service-level meaning, and change authorization
- define verification steps for conflicts and source-of-record checks
- require confirmation before changing production services, approving changes, modifying tickets or service levels, changing access, or communicating unsupported service claims
