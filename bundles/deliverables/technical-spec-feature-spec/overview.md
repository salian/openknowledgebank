# Technical and Feature Specification Overview

Confirm problem, users, outcomes and authority; inspect current architecture and behavior; define scope, non-goals, flows, states, functional behavior, interfaces, schemas, errors, quality attributes, security, privacy, accessibility and observability; trace assumptions and dependencies; document options, decisions, verification, migration, rollout, rollback, ownership, change control and approval.

## Evidence Contract

Relevant evidence includes approved problem and outcome, user research, current system and architecture versions, interfaces and schemas, design decisions, functional and quality needs, security privacy accessibility and safety constraints, dependency owners, prototypes and feasibility evidence, estimates and assumptions, verification plan, migration and rollback evidence, review decisions, and approvals. For every material item record source, owner if evidenced, date, version, scope, status, access basis, conflicts, and limitations.

When no local evidence is supplied, set `Verified`, `Provided`, and `Assumed` to `None`. Put exact missing artifacts under `Needs verification`. A general disclaimer is not a substitute for requesting evidence.

## Boundary

Analysis and drafting do not establish user need, current behavior, requirement, interface, schema, dependency, feasibility, estimate, implementation state, verification result, acceptance, or approval. Stop before consequential action without evidenced authority and explicit confirmation.
