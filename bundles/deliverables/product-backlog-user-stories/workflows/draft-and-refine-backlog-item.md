# Draft and Refine a Backlog Item

1. State the requested outcome and the Product Goal, or mark both as `Needs verification`.
2. Inventory evidence: user or stakeholder, problem, observed evidence, desired behavior, constraints, dependencies, risk, and source of record.
3. Label each fact `Verified`, `Provided`, `Assumed`, or `Needs verification`.
4. Choose an item shape. Use a user-story format only if it clarifies the outcome; Scrum does not mandate that format.
5. Describe the smallest coherent slice and state non-goals.
6. Write observable acceptance criteria, including relevant edge cases and quality constraints.
7. Ask the team that will do the work to size it using the team's current convention. Do not invent a number.
8. Explain Product Goal alignment and ordering rationale, including missing inputs and confidence.
9. Run the quality check and identify open questions and accountable confirmation.
10. Show the proposed item before any tracker or roadmap write. Require explicit confirmation for a live change.

## Output Contract

The visible result contains: direct answer, evidence status, item, acceptance criteria, alignment, ordering rationale, non-goals, dependencies, risks, open questions, confirmation boundary, and Source note.

## Source Note

Use the Scrum Guide for Product Backlog, Product Goal, refinement, and sizing terms. Use the user's current product evidence for scenario claims. Missing local evidence remains `Needs verification`.
