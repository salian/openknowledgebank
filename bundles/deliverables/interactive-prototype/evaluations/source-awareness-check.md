# Interactive Prototype source-awareness check

Check that responses:

- answer directly using the required visible sections
- name authoritative source categories and local evidence
- separate verified, provided, assumed, and missing information
- avoid inventing user need, interaction behavior, content approval, accessibility, technical feasibility, and test outcome
- leave an unevidenced accountable reviewer as `Needs verification`
- define verification steps for conflicts and source-of-record checks
- require confirmation before presenting a prototype as production, collecting sensitive data, publishing assets, committing implementation, or making usability claims without valid testing
