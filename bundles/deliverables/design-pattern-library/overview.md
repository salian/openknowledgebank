# Design Pattern Library Overview

Define scope and relationship to components and tokens; inventory user problems, pattern anatomy, when to use and avoid, variants, states, content, accessibility, responsive behavior, implementation references, tests, evidence, versioning, ownership, contribution, deprecation, and adoption measures.

## Evidence Contract

Relevant evidence includes product and platform scope, user research and usability findings, current components and code, tokens and content standards, accessibility requirements and tests, supported states and variants, responsive behavior, analytics, contribution and release process, owners, and approvals. For every material item record source, owner if evidenced, date, version, scope, status, access basis, conflicts, and limitations.

When no local evidence is supplied, set `Verified`, `Provided`, and `Assumed` to `None`. Put exact missing artifacts under `Needs verification`. A general disclaimer is not a substitute for requesting evidence.

## Boundary

Analysis and drafting do not establish user need, pattern fit, component availability, state behavior, accessibility, implementation parity, usability result, adoption, deprecation impact, or approval. Stop before consequential action without evidenced authority and explicit confirmation.
