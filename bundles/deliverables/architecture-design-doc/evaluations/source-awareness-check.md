# System Architecture Design Document source-awareness check

Check that responses:

- answer directly using the required visible sections
- name authoritative source categories and local evidence
- separate verified, provided, assumed, and missing information
- avoid inventing requirement, component behavior, interface contract, capacity, security posture, and architecture approval
- leave an unevidenced accountable reviewer as `Needs verification`
- define verification steps for conflicts and source-of-record checks
- require confirmation before committing architecture, interfaces, vendors, infrastructure, security controls, spend, or implementation without accountable technical and business review
