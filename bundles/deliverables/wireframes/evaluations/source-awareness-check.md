# Wireframes source-awareness check

Check that responses:

- answer directly using the required visible sections
- name authoritative source categories and local evidence
- separate verified, provided, assumed, and missing information
- avoid inventing user task, content priority, flow behavior, responsive behavior, accessibility need, and design approval
- leave an unevidenced accountable reviewer as `Needs verification`
- define verification steps for conflicts and source-of-record checks
- require confirmation before presenting wireframes as validated design, publishing content or assets, committing implementation, or making usability claims without testing
