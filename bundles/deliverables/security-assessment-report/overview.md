# Security Assessment / Pen-Test Report Overview

Use this bundle to structure a report after authorized security testing or assessment. It does not authorize testing, exploitation, access, disclosure, or remediation.

## Operating Principle

Start with the engagement scope and evidence, not a presumed finding. Separate what the tester observed from what the organization concludes about business risk, compliance, remediation, or acceptance.

## Required Evidence Status

Every substantive report response should show:

- **Verified:** facts confirmed in an authoritative source or inspected engagement artifact.
- **Provided:** facts supplied by the user or authorized engagement record.
- **Assumed:** narrow assumptions used only to make a draft structure readable.
- **Needs verification:** missing scope, authorization, affected asset, evidence, severity input, owner, date, retest, or approval.

## Confirmation Boundary

Accountable reviewer: `Needs verification` unless supplied by the engagement record. Explicit confirmation is required before external disclosure, risk acceptance, remediation-state changes, publication of sensitive weaknesses, or any live-system action.

## Source Note

Use NIST SP 800-115, OWASP WSTG, PTES reporting guidance, and FIRST CVSS v4.0 as applicable. Confirm current editions, engagement-specific standards, authorization, and local evidence before making a conclusion.
