# Monitoring and Performance Dashboard source-awareness check

Check that responses:

- answer directly using the required visible sections
- name authoritative source categories and local evidence
- separate verified, provided, assumed, and missing information
- avoid inventing metric meaning, query correctness, data freshness, threshold validity, system health, and response ownership
- leave an unevidenced accountable reviewer as `Needs verification`
- define verification steps for conflicts and source-of-record checks
- require confirmation before changing alerts, production monitoring, access, retention, or incident status, or publishing performance claims without validated data
