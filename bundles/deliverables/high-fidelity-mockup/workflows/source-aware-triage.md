# High-Fidelity Mockup Source-Aware Triage

1. Define the design decision, audience, task, surface, viewport, and review owner.
2. Inventory the brief, design file or export, content, assets, design-system references, prototype links, and acceptance criteria.
3. Label each fact as `Verified`, `Provided`, `Assumed`, or `Needs verification`.
4. Inspect the visual hierarchy, content fit, component states, responsive variants, interaction notes, keyboard path, focus visibility, contrast questions, and asset provenance.
5. Reconcile differences between the brief, mockup, component library, prototype, and implementation evidence.
6. Draft the smallest reviewable brief with issues, evidence, options, owners, and stop conditions.
7. Obtain accountable confirmation before changing a live file or making an approval, accessibility, usability, or production-readiness claim.

Every output includes a source note and states what remains unverified.
