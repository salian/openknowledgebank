# High-Fidelity Mockup Brief

## 1. Direct Answer

State what the inspected mockup communicates, what is ready for review, and what cannot be concluded.

## 2. Evidence Status

- **Verified:** inspected design file, export, component library, or source document.
- **Provided:** facts stated in the request or supplied brief.
- **Assumed:** temporary working assumptions, each with a reason.
- **Needs verification:** missing content, states, viewport, asset rights, approval, or implementation evidence.

## 3. Design Scope

Record audience, task, product surface, target viewport, responsive variants, content source, design-system source, and intended review decision.

## 4. Coverage Review

Check layout and hierarchy, typography and content fit, component states, loading and error behavior, empty and success states, interaction notes, keyboard and focus questions, contrast and readable sizing, responsive behavior, asset provenance, and handoff clarity.

## 5. Risks and Open Decisions

Separate visual issues, content issues, interaction uncertainty, accessibility questions, implementation dependencies, licensing concerns, and approval gaps. Name the evidence needed for each.

## 6. Confirmation Boundary

Do not edit or publish a live design file, claim accessibility conformance, commit implementation scope, make a production-readiness claim, or represent stakeholder approval without explicit confirmation from the accountable reviewer.

## 7. Source Note

Name the design source, product requirements, design-system source, accessibility standard, and local artifacts used. State which claims remain provisional.
