# Design Handoff Specification Overview

Define feature scope and source file versions; map flows, screens, components, tokens, breakpoints, states, interactions, motion, content, accessibility, assets, data and error behavior, analytics, dependencies, open decisions, acceptance criteria, review, and change control.

## Evidence Contract

Relevant evidence includes approved scope and design links, node and component versions, flows and states, design-system mappings, tokens and breakpoints, content and localization, interaction and motion behavior, accessibility requirements and tests, asset provenance, data and error states, analytics, engineering constraints, acceptance criteria, and approvals. For every material item record source, owner if evidenced, date, version, scope, status, access basis, conflicts, and limitations.

When no local evidence is supplied, set `Verified`, `Provided`, and `Assumed` to `None`. Put exact missing artifacts under `Needs verification`. A general disclaimer is not a substitute for requesting evidence.

## Boundary

Analysis and drafting do not establish design finality, node version, component mapping, token value, interaction behavior, asset right, accessibility conformance, engineering feasibility, estimate, implementation parity, or approval. Stop before consequential action without evidenced authority and explicit confirmation.
