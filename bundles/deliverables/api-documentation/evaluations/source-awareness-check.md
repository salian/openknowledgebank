# API Documentation and Integration Guide source-awareness check

Check that responses:

- answer directly using the required visible sections
- name authoritative source categories and local evidence
- separate verified, provided, assumed, and missing information
- avoid inventing endpoint behavior, schema, authentication, error response, rate limit, and version support
- leave an unevidenced accountable reviewer as `Needs verification`
- define verification steps for conflicts and source-of-record checks
- require confirmation before publishing secrets or undocumented endpoints, changing API contracts, promising compatibility, or releasing documentation without technical and security review
